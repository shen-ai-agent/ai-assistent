Thành phần

Python Voice Server (server/)

  • FastAPI + WebSocket, chạy ở localhost
  • Load model STT/TTS một lần lúc khởi động, giữ trên GPU
  • Không biết gì về Claude ngoài interface Bridge.ask()

Web (web/)

  • Thu mic, push-to-talk, hiện trạng thái và transcript
  • Phát audio theo hàng đợi, dừng được ngay
  • Không xử lý AI. Chỉ là lớp vào/ra

Khái niệm cần biết

STT (Speech-to-Text)

Chuyển giọng nói thành chữ. Ở đây dùng họ model Whisper chạy local.

TTS (Text-to-Speech)

Chuyển chữ thành giọng nói. Cần model hỗ trợ tiếng Việt và đọc ổn thuật ngữ tiếng Anh.

Code-switching

Nói lẫn hai ngôn ngữ trong một câu: "cái NAT Gateway này khác Internet Gateway sao". Đây là phần khó nhất của dự án.

WER (Word Error Rate)

Tỉ lệ từ sai = (thay thế + xoá + chèn) / số từ đúng. Càng thấp càng tốt. 10% nghĩa là cứ 10 từ sai 1.

Term recall

Metric tự định nghĩa: số thuật ngữ nhận đúng / tổng số thuật ngữ. Quan trọng hơn WER vì sai thuật ngữ thì Claude hiểu sai câu hỏi.

RTF (Real-Time Factor)

Thời gian xử lý / thời lượng audio. RTF 0.2 nghĩa là câu 10 giây xử lý mất 2 giây.

VAD (Voice Activity Detection)

Tự phát hiện lúc bắt đầu và kết thúc nói. Để Phase 5; v1 dùng push-to-talk cho chắc.

initial_prompt / hotwords

Đoạn text gợi ý đưa vào Whisper trước khi nhận dạng. Đưa glossary vào đây giúp model viết đúng thuật ngữ mà không cần train.

Post-correction

Bảng thay thế sau STT: "nát gết uây" → "NAT Gateway". Rẻ, hiệu quả, nhưng dễ bị overfit nếu không kiểm tra trên tập riêng.

Normalize (TTS)

Biến text "viết" thành text "đọc": bỏ markdown, đọc số, đọc viết tắt (EC2 → "i xi hai").

Barge-in (ngắt lời)

Đang đọc thì người dùng nói chen vào. Trợ lý phải dừng ngay và nghe.

Held-out set

Phần dữ liệu test giữ riêng, không dùng khi chỉnh glossary/correction, để đo xem cải thiện có thật hay chỉ là học thuộc.

D. Báo cáo

Definition of Done

🚦 Điểm quyết định: có fine-tune STT không?
  • Term recall holdout ≥ 90% → không fine-tune, đi tiếp Phase 2.
  • 80–90% → đi tiếp, bổ sung correction khi dùng thật, xem lại ở Phase 5.
  • < 80% sau khi đã có prompt + correction → đưa fine-tune LoRA vào Phase 5, và ghi thêm dữ liệu từ bây giờ.
